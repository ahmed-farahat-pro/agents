Droob Platform

A bilingual (Arabic/English) student–instructor learning platform deployed on STC Cloud infrastructure inside Saudi Arabia. The platform empowers educators with professional tools and students with engaging learning experiences.

Overview

Droob is a comprehensive e-learning ecosystem built for the Saudi market. It connects instructors who create and monetize courses with students seeking quality education. The platform is fully bilingual, security-first, and built on enterprise-grade infrastructure.

Version: Draft v2 — Refined for engineering execution  ·  Region: Saudi Arabia (STC Cloud)  ·  Timeline: 9 months to MVP launch

Executive Summary

Droob consists of three front-ends and a shared backend:

Instructor Web App

Course authoring, video upload, student management, analytics, subscription billing.

Student Mobile Apps

Native iOS (Swift/SwiftUI) and Android (Kotlin/Jetpack Compose) for course discovery, video streaming, quizzes, assignments.

Admin Web App

Platform operations, instructor moderation, subscription management, content review, financial reporting.

Commercial Model

Dual-sided marketplace:

  • Instructors pay SaaS subscription (tiered on storage, students, courses)
  • Students purchase individual courses from instructors
  • Platform takes commission per sale (15–20%)
  • Transparent financial tracking with monthly payouts

Core Challenges

  • Scalable VOD Pipeline: Handle 3,000+ concurrent streams with automatic encoding to HLS
  • Bilingual UX: Full Arabic/English support with RTL layout compatibility
  • Secure Monetization: Safe payment processing via Saudi payment gateways
  • Future AI Tutor: Course-grounded AI assistant (Phase 3)

High-Level Architecture

Architectural Invariants

  • Backend API must never stream video bytes
  • All video delivered as HLS only
  • All uploads are asynchronous
  • Encoding always queued (never on API threads)
  • CDN is mandatory for delivery
  • Signed URLs required for all media assets
  • No secrets in code (Vault-based only)
  • Idempotency keys on all external side-effects

Technology Stack

Backend

  • Runtime: Node.js 20 + NestJS (TypeScript)
  • Database: PostgreSQL 16 (primary + 1 read replica)
  • Cache & Queues: Redis 7 (BullMQ for async jobs)
  • Object Storage: STC S3-compatible (raw + HLS output)
  • Auth: JWT (15 min access, rotating refresh tokens)
  • OTP: SMS via Unifonic/Taqnyat (Saudi providers)

Frontend

  • Framework: React 18 + TypeScript + Vite
  • Styling: Tailwind CSS + shadcn/ui + custom RTL tokens
  • State: TanStack Query + Zustand
  • i18n: react-i18next (Arabic/English, auto-RTL)
  • Forms: React Hook Form + Zod validation

Mobile

  • iOS: Swift 5.10, SwiftUI, AVPlayer for HLS
  • Android: Kotlin 2.x, Jetpack Compose, ExoPlayer (Media3)
  • API Clients: OpenAPI-generated, identical feature parity

DevOps & Observability

  • CI/CD: GitHub Actions → STC registry → SSH/Ansible deploy
  • Monitoring: Prometheus + Grafana (self-hosted)
  • Logging: Structured JSON via pino, exported to Loki
  • Tracing: OpenTelemetry → Tempo/Jaeger
  • Error Tracking: Sentry for real-time alerts

Video Pipeline

The video pipeline is the highest-risk, highest-leverage subsystem. It must work flawlessly on day one.

Upload Phase

  • Resumable uploads via tus.io protocol over HTTPS
  • Parallel chunk uploads (max 4 concurrent, 8 MiB per chunk)
  • Checksum verification per chunk (SHA256)
  • Upload resumable for 48 hours if connection drops
  • Pre-flight quota checks against instructor's plan limits
  • MIME validation + ClamAV virus scan + ffprobe inspection

Encoding Phase

  • Auto-queued to BullMQ after upload completion
  • Dedicated encoding workers (auto-scale 1→5 based on queue depth)
  • Priority lanes: interactive → standard → bulk
  • FFmpeg generates 4 renditions + master HLS playlist
  • Timeout: max(90min, 4× video duration)
  • 3 automatic retry attempts with exponential backoff

Playback Phase

  • Signed URLs for master playlist (4-hour expiry)
  • CDN caches segments aggressively (7+ days)
  • Target ≥92% cache hit ratio
  • Adaptive bitrate handled by AVPlayer / ExoPlayer natively
  • Progress reported to backend every 10 seconds for analytics
  • Token bound to user + IP CIDR + device fingerprint

Anti-Piracy (v1): Signed URLs, short expiry, token binding, watermark overlay on clients. Phase 2: Widevine/FairPlay DRM if piracy observed at scale.

Security

Authentication & Authorization

  • JWT: 15-minute access tokens + 30-day rotating refresh tokens
  • OTP: 6-digit SMS, 5-minute TTL, max 5 attempts
  • Password: Argon2id hashing — no plain text ever
  • Admin: Mandatory 2FA (TOTP), 8-hour session max, no refresh
  • Mobile: Certificate pinning + client attestation validation

Data Protection

  • Encryption: TLS 1.2+ everywhere, AES-256 at rest
  • Secrets: HashiCorp Vault with KMS envelope encryption
  • PII: All stored inside Saudi Arabia on STC (PDPL compliance)
  • Audit Logging: Every admin action logged with before/after state

Signed URL Spec

  • Signing: HMAC-SHA256(videoId|userId|exp|scope)
  • Binding: User ID + IP CIDR (/24) + device fingerprint
  • Expiry: 4 hours for playlists, auto-refresh at 3h 55m
  • Abuse Detection: Revoke token if seen from >3 IPs or >3 devices in 4h

Student Course Purchases

  • Gateway: Moyasar (primary) or HyperPay (backup)
  • Methods: mada, Apple Pay, STC Pay, Visa, Mastercard
  • Commission: Platform takes 15–20% per sale
  • Refund Window: 7 days if watched <20% of course content
  • Payout: Monthly batch on the 5th for preceding calendar month

v1 Design: Admin-gated subscription changes. Instructors submit change requests; admin approves/rejects. No automatic prorating. Gives full control to finance team while platform matures.

Infrastructure (STC Cloud)

Production Environment (v1 — 3,000 concurrent streams)

  • API Cluster: 3× VM (4 vCPU, 8 GB RAM) behind load balancer
  • Encoding Workers: 2× VM (8 vCPU, 16 GB RAM), auto-scale to 5
  • PostgreSQL: 1× primary (8 vCPU, 32 GB RAM, SSD) + 1× read replica
  • Redis: 1× VM (2 vCPU, 8 GB RAM) with persistence enabled
  • Object Storage: STC S3-compatible, starting 5 TB, elastic
  • CDN: Bunny or Cloudflare in front of object storage

Backups & DR

  • Database snapshots every 6 hours, retained 30 days
  • WAL archiving for point-in-time recovery
  • RPO: 1 hour  |  RTO: 4 hours

Compliance & Data Residency

  • PDPL: Personal Data Protection Law (Saudi Arabia)
  • Data Residency: All PII and content stored inside Saudi Arabia on STC
  • CITC: Communications and IT Commission alignment
  • ZATCA: Tax authority e-invoicing for B2B instructor transactions
  • Consent: Explicit user consent at signup, right to data export/deletion
  • Audit Log: Complete access audit trail for all sensitive operations

Risks & Mitigations

R1 — CDN egress costs explode

Mitigation: Default to 480p, aggressive cache TTLs, per-instructor bandwidth caps, monthly cost alerts.

R2 — Encoding queue backs up

Mitigation: Auto-scale workers, priority queue, admin alerts on backlog >50 jobs.

R3 — Video piracy

Mitigation: Signed URLs, watermarks. Escalate to DRM if observed at scale.

R4 — Apple IAP rejection

Mitigation: Apple requires in-app purchase for digital content. Evaluate IAP (15–30% cut) vs. positioning as educational service. Legal decision needed before Phase 2.

R5 — Saudi payment gateway limits

Mitigation: Use "collect then monthly payout" model if gateways don't support marketplace splits natively.

R6 — Bilingual QA complexity

Mitigation: Dedicated QA matrix, RTL reviewer in every sprint, Arabic copywriter on retainer.
